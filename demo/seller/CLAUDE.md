# Paylane 랜딩 (판매자 세션)

이 폴더에는 핀테크 해외송금 앱 "Paylane" 의 랜딩 페이지 `index.html` 하나가 있다.
사용자가 결함을 하나씩 지목하면 그것만 고친다. 이 세션의 매 턴은 훅이 자동으로
(프롬프트, diff, 스크린샷, 검사 결과, 아래 step-note) 를 한 "단계" 로 기록해 기억 팩이 된다.
**기록의 품질이 곧 상품의 품질이다.**

## 규칙 1: 한 턴에 한 가지 결함만
- 사용자가 지목한 결함 하나만 고친다. 눈에 띄는 다른 문제는 고치지 말고 마지막에 한 줄로 언급만 한다.
- 고치는 데 필요한 최소한의 CSS 규칙·요소만 바꾼다. 색 체계, 폰트, 여백 체계를 통째로 바꾸지 않는다.

## 규칙 2: 승인된 섹션은 재작성하지 않는다
- 사용자가 "나머지는 승인", "다른 건 그대로" 라고 한 섹션(히어로 등)은 **다시 쓰지 않는다.**
- `Write` 로 파일 전체를 다시 쓰지 말고, 해당 선택자의 규칙만 `Edit` 한다. (edit_mode = targeted)
- 부득이하게 구조를 바꿔야 하면(rewrite) 먼저 왜 targeted 로는 안 되는지 한 문장으로 말하고 진행한다.

## 규칙 3: 디자인 파일을 고친 턴의 끝에는 반드시 step-note
`index.html` 을 고친 턴은 답변 **맨 끝**에 아래 형식의 코드 블록을 정확히 하나 남긴다.
훅이 이 블록을 읽어 단계 기록의 `intent / why / lesson / verdict` 를 채운다. 블록이 없으면 그 턴은 기록 품질이 떨어진다.

```step-note
{
  "intent": "fix",
  "target": ".hero .btn-primary",
  "why": "반투명 흰 배경이 보라 그라데이션 위에서 대비 2.5:1 로 떨어졌다. 배경을 불투명 #0b1020 으로 바꿔 15:1 을 확보했다.",
  "lesson": "그라데이션 히어로의 주 CTA 는 반투명(glass) 배경을 쓰지 말고, 배경색과 무관하게 대비가 보장되는 불투명 단색을 쓴다.",
  "verdict": "accepted"
}
```

필드 규칙:
- `intent`: `init`(첫 작성) · `fix`(결함 교정) · `revert`(되돌림) · `polish`(결함 아닌 다듬기) 중 하나
- `target`: 실제로 고친 CSS 선택자 (여러 개면 쉼표로)
- `why`: 무엇이 왜 문제였고 어떻게 고쳤는지, 수치를 포함해 1~2문장 (측정한 값·바꾼 값)
- `lesson`: 다음에 **다른 랜딩**을 만들 때 그대로 적용할 수 있는 일반 교훈 1문장. 선택자 패턴이나 수치를 포함한다. 없으면 `null`
- `verdict`: `accepted`(사용자가 승인했거나 아직 이의 없음) · `rejected`(사용자가 되돌리라 함) · `partial`(일부만 반영)
  - 사용자가 이전 턴 수정을 되돌리라고 하면 그 턴은 `intent: "revert"`, `verdict: "rejected"` 로 기록한다.

## 규칙 4: 확인은 검사 도구로
고친 뒤 결과를 확인하고 싶으면 `node C:/mm/tools/check.mjs index.html` 을 실행한다.
출력 JSON 의 `failed` 에 방금 고친 항목이 남아 있으면 같은 턴 안에서 마저 고친다.
검사 5항목: `cta-contrast` `h1-lines` `no-hscroll` `card-height` `nav-overlap`.

## 하지 말 것
- `.mm/` 폴더(세션 상태·단계 기록)를 읽거나 고치지 않는다. 훅이 관리한다.
- 외부 폰트·CDN 을 추가하지 않는다. 파일 하나로 열려야 한다.
- 이미지 파일을 새로 만들지 않는다.
